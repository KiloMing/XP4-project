# 教学流程

目标：按所选路线完成可复核的实验，并能独立理解、修改和调试核心流程。V1.0 保留原标准；视觉路线使用 [24 课计划](VISION_LANDING_PLAN.md)，分别记录进度。

1. 每次先读 CURRENT 与最近 daily，用 5～10 分钟无答案小测试回顾。
2. 模型 → 一次最小完整示例 → 补关键代码 → 撤去提示 → 独立复现 → 变式 → 排错 → 延迟复测。
3. 每次仅引入一个主要新概念；先预测结果，再运行，再解释差异。
4. API 同时讲参数、单位、返回值、异步行为、生命周期和失败路径。
5. 不一次性代写整套任务程序；首次示例与卡点对照可以提供完整小例子。
6. 允许查文档；独立复现指自己组织逻辑，不要求默写第三方接口。
7. 跟随跑通、源码归档、独立掌握分别记录；未实测明确标注。
8. 实际 Ubuntu 最终源码与日志归档后才记录为可复现，不用聊天草稿冒充最终代码。
9. 学习者决定项目范围。本次已明确增加静态 AprilTag 视觉路线；不因此修改旧 ROS 2、PX4、MAVSDK 源码，也不扩展为移动平台、真机或清洁功能。

每天记录：目标、实际完成、问题与原因、证据路径、提示程度、下一次测试。阶段完成要求能解释、能运行、能独立写最小实现、能改需求并定位至少一个问题。

## 视觉课怎么讲

每课先说清“这一步解决什么问题、输入从哪里来、输出交给谁”，再用图或一个数值例子解释原理。执行命令前说明运行目录、环境、参数、预期输出、失败意味着什么；不要一次贴出六个终端的整套启动命令让学习者照抄。

一次 90～120 分钟：约 10 分钟回顾，15～20 分钟讲原理，45～60 分钟做最小实验，15～20 分钟做变式或排错，最后 10 分钟归档。遇到环境问题可以整课只定位一个问题，按实际进度顺延。

必须讲清：像素与米、相机光学系与机体系、ENU/NED 与 FLU/FRD、采样时间与接收时间、目标可见与位姿新鲜、命令被接受与动作已完成。每次用一项预测和实测对照检查理解，不能只问“懂了吗”。

每课记录“未开始 / 有指导实践 / 验收通过 / 独立复现”，附对应证据。阶段验收以三课材料为准；上游 README、截图、录像与性能数字只作参考，不能写成本项目实测。阈值先注明为设计值；调整时写原因，不能看到结果后改标准来制造通过。

排错顺序：先看真实输出，再确认环境、话题与类型、QoS、时间、坐标、状态机，最后才调控制参数。每次只变一个条件，保留失败样本。只有静态定位和非视觉 Offboard 均通过后，才接视觉下降。
