# 个性化学习计划

## 起点与目标

依据 LINUX-STUDY 截至 2026-10-14 的记录：已有 Linux、Socket、CMake、ROS 2、Gazebo、TF 与导航联调经历；已有单点/巡检运行记录，但部分最终源码、独立复现及异常测试证据未归档。MASTERY 的较早记录不能覆盖 CURRENT 的近期实践，也不能把近期引导运行自动升级为独立掌握。

不从零重学 Linux，不要求先修好旧 RGB-D/SLAM 工程。聚焦 PX4 状态、MAVSDK 命令/遥测、坐标高度和可靠 C++ 状态机。

建议约 8 周、60～80 小时，每周 8～12 小时。时间是估算，按验收推进；已独立掌握的内容可以缩短，未通过则有针对性回补。

## 具体练习

### 阶段 1

理解 SITL、MAVLink 与 MAVSDK、武装/解除武装、飞行模式及故障保护；绘制数据流。先用 QGC 建立人工操作基线，不深入 PX4 PID 或控制器源码。

### 阶段 2

先诊断 CMake、enum class、struct、lambda、steady_clock 基础。仅回补不会的内容。
只读程序显示连接、health、position、flight_mode、in_air、armed、landed_state 及接收时间。遥测回调只更新快照；控制循环读取快照，正确同步共享数据，避免回调中长等待。
关闭 SITL 验证断连或数据过期检测；不让旧数据被当作当前有效数据。

### 阶段 3

分为检查/解锁、起飞/稳定、降落/停转三个小任务。记录每个 API 返回值和状态变化。解释为什么 takeoff 成功不代表达到 3m。查明 Gazebo 电机转速观测渠道，不以 armed=false 替代转速证据。

### 阶段 4

纸面练习 ENU/NED、经纬度、海拔/相对/离地高度。H 海拔 100m、巡航平面高于 H 3m 时，goto_location 绝对高度应为 103m。实际使用首次有效位置及已验证变换，不硬编码该示例值。
配置 H 与 A 距离约 10m，4m×4m 同高静态平台。校验碰撞体、坐标和平台中心，再飞行。

### 阶段 5

首次 H 不变；等待从停转确认后开始；等待结束必须重新检查。先单轮再循环。

### 阶段 6

从早期使用状态枚举，逐步完善。每状态说明进入动作、成功条件、超时与失败出口。先用假遥测注入永不到位、未知着陆状态、数据停更，再做 SITL 受控异常。

### 阶段 7～8

完成 TEST_PLAN。独立写最小遥测程序和一个带超时的状态；将唯一目标 A 改到另一安全位置并复测；独立定位一次错误；隔几天复述或复现核心逻辑。允许查 API，不照抄完整实现。

## 每次学习（90～120 分钟）

10 分钟回顾；15～20 分钟一个新概念；45～60 分钟自己实践；15～20 分钟变式或排错；10 分钟记录。
每周安排 4～5 次，考试周减量并顺延，不降低验收标准。
