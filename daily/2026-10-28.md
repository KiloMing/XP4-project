## 安装方案与还没锁定的版本

Agent v2.4.3、px4_msgs v1.17.0 标签按本次提供的安装方案记下，**实际安装版本和 checkout commit 待实测**。仓库没有这两个依赖的源码或版本锁文件，现有截图也没有它们的 Git 输出。不能因为通信通了，就断言本机一定用的是这两个标签。

下面是按该方案整理的安装步骤，不是当时终端操作的逐字记录，也没有在 Codex 中重新执行。已有可用安装时先核对版本，不重复安装或覆盖已有目录。Ubuntu 上需要已有 Git、CMake、C++ 构建工具、Jazzy 和 colcon；缺少哪个再补哪个。

Agent 源码安装方案（仅在尚未安装、目标目录不存在时使用）：

```bash
cd ~
git clone --branch v2.4.3 https://github.com/eProsima/Micro-XRCE-DDS-Agent.git
cd Micro-XRCE-DDS-Agent
cmake -S . -B build
cmake --build build -j2
sudo cmake --install build
sudo ldconfig
command -v MicroXRCEAgent
```

px4_msgs 工作区方案（已有 `src/px4_msgs` 时先检查其版本，不再 clone）：

```bash
source /opt/ros/jazzy/setup.bash
mkdir -p ~/vision_landing_ws/src
cd ~/vision_landing_ws/src
git clone --branch v1.17.0 https://github.com/PX4/px4_msgs.git
cd ~/vision_landing_ws
colcon build --packages-select px4_msgs
source install/setup.bash
ros2 pkg prefix px4_msgs
ros2 interface show px4_msgs/msg/VehicleLocalPosition
```

若标签找不到或构建失败，保留实际报错再核对版本，不直接换 main 后声称复现成功。以上只整理 Agent 和消息包方案；Ubuntu、ROS 和 Gazebo 的完整安装历史尚未归档。

## 下次从新终端怎样启动

以下用于下一次复现；本次尚未独立重启验收。保持原来的普通 X500，不加入相机或自定义 world。

终端 1：启动 Agent，保持运行。

```bash
MicroXRCEAgent udp4 -p 8888
```

终端 2：启动原有 PX4 SITL。

```bash
cd ~/px4_ws/PX4-Autopilot
make px4_sitl gz_x500
```

在 PX4 的 `pxh>` 控制台检查客户端：

```text
uxrce_dds_client status
```

若客户端已连接就不重复启动。同机仿真且客户端未启动时，再在 `pxh>` 输入以下命令；跨主机时地址要换成 Agent 所在主机，不能照搬 localhost。

```text
uxrce_dds_client start -t udp -h 127.0.0.1 -p 8888
```

终端 3：每次新开终端都加载 Jazzy 和消息包工作区，再查询真实话题。

```bash
source /opt/ros/jazzy/setup.bash
source ~/vision_landing_ws/install/setup.bash
ros2 pkg prefix px4_msgs
ros2 topic list
ros2 topic info -v /fmu/out/vehicle_local_position_v1
ros2 topic echo /fmu/out/vehicle_local_position_v1 --qos-reliability best_effort
```

截图中该话题有 1 个 publisher，发布端是 BEST_EFFORT、TRANSIENT_LOCAL，所以这里明确使用 best_effort 接收。最后的截图能看到 heading、ref_lat、ref_lon、dist_bottom 等字段；这证明当时收到了消息，不证明所有字段有效或已经持续接收 30 秒。停止时先 Ctrl+C 退出 echo，结束仿真，再结束 Agent；本轮只读通信，不发送控制命令。

## 排错时我学到的

| 遇到的问题 | 这次怎么定位 | 下次先查什么 |
|---|---|---|
| 找不到 Agent | 本次用户确认的早期问题；原始报错未取得 | `command -v MicroXRCEAgent`；分清没安装和不在 PATH，按上面的方案核对 |
| 能看到话题，却不能 echo | 截图显示 `Package not found`、`Unknown package 'px4_msgs'`、消息类型 invalid | 安装/编译 px4_msgs 后 source 工作区；只 source Jazzy 并不提供这个消息包 |
| 位置话题提示 Unknown topic | 写成了不带后缀的 `/fmu/out/vehicle_local_position` | 先看 `ros2 topic list`；本次实际名称带 `_v1` |
| 换成正确话题仍报消息类型 invalid | 当时消息包仍不可用 | 话题名和消息包是两个问题，分别用 topic info 与 interface show 检查 |

这次最有用的区别是：发现话题不等于本机有消息定义，有消息定义也不等于已经收到数据。以后先确认这三步，不急着重装整个环境。截图还出现过 `Topic type hash: INVALID`；这里不把它单独解释成版本不兼容的证据。
